# Анализ проекта и переход на Laravel

В исходном проекте использовался Strapi 5.47.1, а не платёжный Stripe. React 19, Vite, TypeScript и TanStack Query уже отделены от backend. Клиентская интеграция сосредоточена в `client/src/api`, что позволяет сохранить страницы и компоненты при замене сервера.

Strapi одновременно обслуживал контент (новости, первый экран, описание клуба, сотрудники, контакты) и предметную логику (команды, членство, капитанство, заявки, снимки составов и матчи). Поэтому одной замены админки недостаточно: перенесены модели, валидация, разграничение доступа и алгоритм сетки. Игроки и администраторы Strapi были разными типами аккаунтов; Laravel объединяет их через явно назначенные роли.

Новая структура:

- Eloquent-модели и миграции в `server/app/Models` и `server/database/migrations`.
- Контроллеры API в `server/app/Http/Controllers`.
- Построение сетки и продвижение победителя в `server/app/Services/BracketService.php`.
- Русская Blade-панель: `server/resources/views/admin`, с приоритетом команд и турниров. Формы контента задаются в `server/config/admin.php`; нет конструктора схем и служебных разделов CMS.
- SQLite для локальной разработки; стандартные внешние ключи, транзакции и блокировки строк для составов, заявок и матчей.
- Sanctum для React, сессии Laravel и CSRF для панели.

Основные пользовательские сценарии сохранены: регистрация и вход, профиль с аватаром, создание команды, несколько дисциплин, создание и добавление игроков, мягкое удаление, передача капитанства с журналом, выбор состава на конкретный турнир, проверка лимита и сроков, принятие/отклонение заявок, отзыв, single-elimination сетка, bye и автоматическое продвижение победителей. Управление заявками и счётом доступно и в панели, и через существующие React-компоненты организатора.

Контракт API сознательно совместим: documentId, camelCase, маршруты и оболочка data сохранены. Параметры populate больше не управляют раскрытием произвольных отношений: backend сам выбирает необходимые данные. Старые названия типов Strapi заменены на ApiListResponse/ApiSingleResponse. React по умолчанию подключается к порту 8000.

При миграции обнаружены черновые и опубликованные дубликаты турниров и контента. Импорт выбирает опубликованную версию и перенаправляет отношения всех исходных ID. В исходных демонстрационных матчах отсутствовали nextMatch/nextSlot; переходы восстанавливаются по координатам сетки. Исходная база открывается только для чтения, повторный импорт в заполненную базу запрещён.

Ограничения перехода: история изменений и служебные настройки Strapi не переносятся, неиспользуемая legacy-сущность participant не включена в новый интерфейс. Редактор новости — обычное текстовое поле; галерея поддерживает добавление нескольких изображений. Операции удаления контента заменяются снятием публикации, чтобы не терять записи. Публикация на сервер и настройка production окружения выполняются отдельно.

Проверки включают интеграционный турнир из трёх команд до финала, права и роли, составы, валидацию заявок, профили/медиа, публикацию контента и импорт на искусственной базе. Реальная база перенесена отдельно; 13 медиафайлов проверены на наличие. В браузере проверены React-команды, состав, панель и турнирная сетка; визуальная проверка админки выполняется на копии базы с отдельным временным аккаунтом.
