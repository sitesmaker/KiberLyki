# КиберЛуки

React 19 + Laravel 12: сайт клуба, новости, команды, личные кабинеты и турниры с single-elimination сеткой.

- `client/` — существующий React + TypeScript + Vite.
- `server/` — Laravel API, публичные HTML-страницы и русская панель управления на Blade.
- `backend/` — прежний Strapi 5, сохранён для сверки и импорта. Для нового сайта запускать его не требуется.

## Локальный запуск

Нужны PHP 8.2+, Composer, Node.js 20.19+ или 22.12+ и SQLite (pdo_sqlite).

```powershell
cd server
composer install
Copy-Item .env.example .env
php artisan key:generate
New-Item -ItemType File database/database.sqlite -ErrorAction SilentlyContinue
php artisan migrate
php artisan storage:link
php artisan serve
```

Если окружение уже подготовлено, достаточно `php artisan serve` из `server/`. Здесь импортированные данные находятся в `server/database/cyberluki.sqlite`; путь задан в локальном `.env`.

В другом терминале:

```powershell
cd client
npm install
Copy-Item .env.example .env
npm run build
npm run dev
```

Сайт: http://localhost:5173. Панель: http://localhost:8000/admin.
При размещении на одном домене `VITE_API_URL` оставляют пустым; Vite проксирует API в Laravel (`http://localhost:8000`). Для разработки публичных страниц сначала нужна сборка и запущенный Laravel.

На Windows с OpenServer, если `composer` сообщает `Could not open input file: \\composer.phar`, задайте `COMPOSER_HOME` и используйте существующий phar:

```powershell
$env:COMPOSER_HOME = Join-Path $env:LOCALAPPDATA 'CyberlukiComposer'
php -d sys_temp_dir="$env:TEMP" D:/OSPanel/modules/PHP-8.2/ospanel_data/default_data/composer/composer.phar install
```

Если OpenServer указывает недоступный каталог временных файлов, запускайте PHP с `-d sys_temp_dir="$env:TEMP"`. Для простого локального сервера без подпроцессов:

```powershell
cd server/public
php -S localhost:8000 -t . ../vendor/laravel/framework/src/Illuminate/Foundation/resources/server.php
```

## Перенос Strapi

Остановите запись в Strapi и сохраните копии `backend/.tmp/data.db` и `backend/public/uploads`. Импорт выполняется только в пустую отдельную базу Laravel, без удаления или изменения исходных данных:

```powershell
cd server
php artisan cyberluki:import-strapi ../backend/.tmp/data.db --uploads=../backend/public/uploads
```

Импорт сохраняет documentId (поэтому ссылки React остаются прежними), bcrypt-пароли пользователей, роли организаторов, профили, дисциплины, команды, составы, передачи капитанства, заявки, снимки игроков, матчи, новости и содержимое сайта. Черновая и опубликованная версии объединяются по documentId с приоритетом опубликованной версии. Связи через любые прежние ID перенаправляются на объединённую запись. В старых демонстрационных сетках недостающие связи следующего матча восстанавливаются по раунду и позиции. Изображения и видео копируются, прежние адреса `/uploads/...` сохраняются.

Активные незаблокированные администраторы Strapi переносятся с прежними email и паролями. Если email уже занят пользователем сайта, импорт не повышает ему права автоматически и выводит предупреждение. Для создания отдельного администратора:

```powershell
php artisan cyberluki:admin
```

Пароль вводится скрыто; минимальная длина — 12 символов. Старые JWT Strapi не действуют: пользователям нужно войти снова.

В текущем переносе: 34 пользователя сайта + 1 администратор, 4 команды, 3 турнира, 6 матчей и 13 медиафайлов. Исходные 6 записей турниров — это 3 пары черновик/публикация. Старые неиспользуемые формы `participants` и настройки служебных плагинов Strapi не участвуют в новом приложении.

## Работа с командами и турнирами

В панели раздел **Команды и составы** позволяет создать команду, выбрать её капитана и дисциплины, изменить название и описание, создать игрока с временным паролем, добавить существующего по точному логину/email, удалить из состава и передать капитанство. Удаление сохраняет аккаунт и турнирную историю. Капитан автоматически входит в состав; один игрок не может одновременно состоять в двух активных командах.

Капитаны могут выполнять те же действия в React на `/cabinet`. На `/cabinet/profile` игрок редактирует свою анкету, аватар и пароль. Для новых паролей требуется минимум 8 символов; вход с прежними паролями сохранён.

В разделе **Турниры и сетки** создайте турнир, выберите дисциплину, размер заявки, лимит команд и даты (время Москвы), включите публикацию и этап «Регистрация». Капитан подаёт заявку на странице турнира в React, выбирая конкретных игроков. Сервер проверяет сроки, дисциплину, состав, повторные заявки и лимит мест; сохраняет снимок состава.

Откройте «Заявки и сетка», примите минимум две заявки и нажмите «Сгенерировать сетку». Посев поддерживает любое количество команд от двух до лимита; свободные места дают автоматический проход. Запишите счёт матча: победитель перейдёт в следующий раунд, после финала турнир завершится. Ничья и повторная запись завершённого матча запрещены. После генерации сетки заявки и основные параметры участников фиксируются.

Организатор работает с командами, турнирами и контентом. Администратор дополнительно назначает права пользователей. Панель использует сессию с CSRF, React — Bearer-токены Sanctum со сроком семь дней. Поле ответа `jwt` и оболочка `{data: ...}` сохранены для совместимости с существующим клиентом; значение `jwt` теперь является токеном Sanctum.

## Проверки

```powershell
cd server
php artisan test
# Если запуск подпроцесса недоступен в OpenServer:
php -d sys_temp_dir="$env:TEMP" vendor/phpunit/phpunit/phpunit --testdox

cd ../client
npm run lint
npm run build
```

Интеграционные тесты работают с отдельной SQLite `:memory:`: авторизация, выход и смена пароля, права капитана/организатора, составы и история, ограничения заявок, сетка с bye до финала, загрузка аватара, страницы админки, публикация контента и импорт Strapi с проверкой неизменности источника. Анализ и решения: `docs/laravel-migration.md`.

Перед публикацией настройте production `.env` (APP_DEBUG=false, HTTPS, домены CORS), корень веб-сервера `server/public`, резервное копирование базы и файлов. Публикация на хостинг в эту миграцию не входит.

SEO настраивается в `/admin/seo`; контентные разделы сгруппированы в меню «Содержимое сайта». Сборка React сохраняется в `server/public/site`. Главная, новости и турниры выдаются Laravel с готовым содержимым и SEO в HTML; React подключает интерактивные блоки. Изменения контента из админки не требуют пересборки. Для production достаточно PHP-хостинга, постоянно работающий Node.js не требуется. При обычном размещении на одном домене API, изображения и SEO используют текущий адрес автоматически. Подробнее: [SEO и публикация](docs/seo.md), [люди клуба и права доступа](docs/club-people-and-access.md).

